## 3. 合并后的统一架构建议（更适合 js agent 的落地形态）

### 3.1 三阶段与安全声明边界

核心纪律：**每个阶段只声明该阶段已验收的性质，不许把终态声明提前**。沿用 K 的证据标签。

| 阶段 | 内容 | 可以宣称 | 不得宣称 |
|---|---|---|---|
| **A：保安上岗**（D P0–P2，Python orind） | 工牌在线核销、打标点、蜜罐、巡逻、阶梯、策略包、审批消毒 | 防模型层提示注入；吊销即时；泄密可探测；全链路审计 | 防 Echo 进程 RCE |
| **B：权限搬家**（K P2–P3 + Build Cell 提前） | Build Cell（shell/code 先行）→ Secret/Network/Connector Cell → File Cell + 提交膜 + 状态机对账 | 凭证、外发、代码执行、工作区写四个面对 RCE 收口；外部提交无重复效果 | 全进程失陷收口（桌面/记忆未迁完） |
| **C：强制模式**（K P5） | Echo 最小 OS 权限、enforce 模式拒绝旧协议、移除 ambient authority | Echo 进程失陷后的结构性收口（限 macOS，经 K§15.6 十条验收） | root/内核失陷、图像注入完全免疫 |

### 3.2 适配 js agent 的六项具体调整

1. **Build Cell 从 K 的 P4 提前到阶段 B 开头**。理由：shell/code 是最大攻击面，且 `os_sandbox.py` 已有子进程沙箱基础，增量最小收益最大。
