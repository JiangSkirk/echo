# Mutation sample — security-bearing surface (2026-08-29)

This is a **local** mutmut 3.7.0 sample. It is **not** a CI gate and does
not claim whole-library mutation coverage.

## 1. Scope

Mutated files (`[tool.mutmut].only_mutate`):

- `js/security/parser.py`
- `js/security/guard.py`
- `js/security/rules.py`
- `js/security/net_guard.py`
- `js/echo/ledger/strict_json.py`
- `js/echo/ledger/journal.py`

`source_paths = ["js"]` so the mutants tree can import the rest of the
package. Tests used for verdicts are listed in
`pyproject.toml` `[tool.mutmut].pytest_add_cli_args_test_selection`.

Reproduce:

```bash
uv run python scripts/run_mutation.py
# or
uv run mutmut run --max-children 4
uv run mutmut results
```

## 3. Real gaps that were tests, then killed

These mutants changed control flow and survived the first pass. New
assertions in `tests/security/test_mutation_kills.py` now kill them:

| Mutant (representative) | Change | Why it mattered |
|-------------------------|--------|-----------------|
| `BehaviorGuard.check_command` mutmut_4 | `hardline = None` | Hardline skipped; `defense_mode=off` would allow `rm -rf /` |
| `check_command` mutmut_6 / 9 | parse result forced `None` / inverted `has_subshell` | Subshell `$(...)` / backticks could slip through |
| `check_command` mutmut_20 | `BLOCK` → `None` on parser exception | Fail-open on parse errors |
| `check_command` mutmut_56 | `if not _parser_understood` inverted | Regex fallback skipped for unparseable high-risk lines (`curl $'…' \| sh`) |
| `check_tool_result` / `check_repeated_failure` / `reset_loop_counters` | (no tests in first selection) | Functions existed in-repo but were outside the mutmut test list |
| `strict_loads` helpers / `require_finite` | unused by property tests | NaN / BOM / bytes / non-object roots were untested |

Also pinned: workspace delete policy, null-byte paths, metadata hostname
block even when DNS returns a public A record.

## 4. Exempt survivors (not a product hole)

Every remaining survivor was classified. Classes:

| Class | Typical mutation | Why exempt |
|-------|------------------|------------|
| Reason / log string | prefix `XX`, case flip | Verdict enum unchanged; tests assert decision type |
| Unused default | `_cwd="."` → `"XX.XX"` | Parameter is unused |
| Extra fail-closed | `BLOCK` constructor arg dropped when the branch is already taken by another check | Equivalent on the tested inputs |
| Journal compaction bookkeeping | `FileEchoLedger.compact`, archive verify helpers | Out of this sample's test selection; covered elsewhere by ledger recovery tests, not re-run here |
| `PinnedTransport.__init__` wiring | constructor field swaps | Constructor-only; pin/connect helpers were not in the selected tests |
| Parser scanner internals | `_scan_*` quote/redirect variants | Many equivalent tokenizations; fail-closed `parse() is None` is the product contract |
| Timeout | infinite-loop mutants | Treated as killed-for-safety in operations; counted separately |

No-tests leftovers are almost all journal archive/recovery internals
(`verified_logical_records`, `_archive_journal_locked`, tail recovery)
plus `net_guard` pin-client factories. Those stay on the exemption list
for this sample.

## 5. What this does not claim

- Whole `js/` mutation coverage
- A CI fail-closed kill-rate floor
- That 1397 survivors are all equivalent (they are classified; journal
  compaction was not re-tested in this sample)
